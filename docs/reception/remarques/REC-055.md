# REC-055 : en fait j'ai enfin mis la main sur ce qui me dérangait dans cette partie, il fau…

en fait j'ai enfin mis la main sur ce qui me dérangait dans cette partie, il faut que les données soient cascadé correctement, j'ai un besoin, ça me créer un cahier des charges, puis ça me créer dans ce cahier des charge des exigences fonctionnelle (et dans le future je les veux teste driven) qui me créer un test pour chaque exigence et ensuite un ticket de teste que soit l’utilisateur valide soit le model valide. donc il faut reprendre tout la structure

## Traitement

**traitee** : La cascade est en place : besoin → cahier des charges de sa version → exigences → un test par exigence (nouveau type TEST-xxx, wikik nouveau test ou « ＋ test » depuis l'exigence) → ticket validé par toi (✓ Je valide / ✗ Échec) ou par le modèle (outil MCP test_valider) ; page Cascade et arbre dans le volet Projet, check signale les exigences sans test.
